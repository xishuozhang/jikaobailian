# 好友 PK 部署与验收

## 部署

1. 在当前微信云开发环境创建集合 `pk_rooms`。权限选择自定义规则，设置为以下内容，禁止小程序客户端直接读取或修改房间。房间包含答案，只允许云函数通过管理员权限访问：

   ```json
   { "read": false, "write": false }
   ```

2. 右键 `cloudfunctions/friendPk`，选择“上传并部署：云端安装依赖”。`engine.js` 必须随函数一起上传。已有的 `users`、`questions` 集合继续使用。
3. 重新编译小程序。用两名体验成员分别在两部手机打开同一体验版本，测试分享邀请。
4. 验收通过后上传小程序、提交审核并发布。只推送 Gitee 不会部署微信云函数或更新线上小程序。

## 对战规则

- 每局从启用题目中抽取最多 10 道有效题，支持单选、多选和判断。两人题目和顺序相同。
- 默认 3 分钟，可选择 1、3、5 分钟。房间等待邀请有效期 15 分钟。
- 双方准备后统一倒数 5 秒。题目在服务器开始时间后才下发。
- 每题确认后保存，不能修改。每道题分值相等，成绩按正确数换算为百分制；正确数更高者胜，同分平局。
- 双方完成或到达服务器截止时间时结算。未确认的题目不计分，未提交成功的网络请求不计分。
- 明确点击退出比赛判负；仅返回、切后台或断线不会立即判负，服务器倒计时继续。再次进入可恢复已确认的进度。
- 房间状态每约 1.8 秒同步一次，计时在本地依据服务器时钟刷新。最后一位离线时无需定时任务，下一次查询会按原截止时间结算。
- PK 独立保存于 `pk_rooms`，本版不写入普通学习记录、分类进度或错题本。
- 再开一局会创建新房间，需要重新分享邀请。

## 双机验收

- A 创建、分享给 B；B 加入，两人分别准备，倒计时后显示相同题目。
- 第三个账号打开同一邀请应提示已满，不能查看题目或答案。
- 测试单选、多选、判断的确认；其中一方答完后等待另一方。
- 分别制造胜利、失败、平局，核对分数和本局解析。
- 关闭网络后确认一道题，再恢复网络，核对进度，不应重复计分。
- 切后台直到超时，再返回，应显示结算结果，不能继续提交。
- 客人等待时退出可重新邀请；房主等待时退出关闭房间；比赛中退出判负。

房间保存了题目快照和双方答案，管理员可定期清理结束时间超过 7 天的房间。对战状态和计分校验已有本地自动化测试，云权限、分享以及跨设备体验仍需在真实云环境验收。
